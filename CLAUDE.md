# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Project

Of Wild & Walls is a wildlife and heritage photography portfolio, rebuilt under **SOW-002** (Phase 2).
One Next.js app holds the public site, the Payload CMS admin (`/admin`) and the API (`/api`).

- **Stack:** Next.js 16 (App Router), Payload CMS 3.93, PostgreSQL 16 (`@payloadcms/db-postgres`), TypeScript, pnpm
- **Storage:** S3-compatible (AWS S3 / Backblaze B2) via `@payloadcms/storage-s3`; local disk when `S3_BUCKET` is unset
- **Hosting:** AWS EC2 — the Next.js server plus a separate background job worker (`pnpm jobs:run`)
- **Admin:** a single admin login used by the client. No roles; anyone signed in has full access.

### Scope (SOW-002) — what is being built
- **Home, Flow view (default):** infinite drag-to-explore canvas in every direction (mouse, trackpad, touch); photos repeat so it never ends; only on-screen tiles load full images
- **Home, Grid view:** a horizontal strip; the Flow/Grid choice is not remembered between visits
- **Theme:** always opens in dark mode, with a light/dark toggle; the choice is not remembered between visits
- **Filters:** Category (with sub-categories), Collections, Location, Camera, Lens, Year (date taken). One option per filter, AND across filters, live counts, options with no photos hidden, Lens narrowed by the selected Camera, shareable filter URLs
- **Search** (title, species, tags) and **sort** (Newest, Oldest, Random)
- **Photo view:** filmstrip, details panel hidden by default, empty fields hidden, Edited/RAW toggle, ambient sound
- **Bulk Upload page (admin):** spreadsheet-style grid of Google Drive links ("Anyone with the link"), dropdown-only categories/collections/locations, background download → storage → EXIF → photo record, per-row progress, retry, duplicate check by Drive file ID, draft saving
- **Out of scope:** visitor accounts, e-commerce, share buttons, Excel/CSV import, multi-select within a filter

## Commands

```bash
pnpm install
docker compose up -d          # local Postgres on :5432 (db: ofwild, user/pass: postgres)
cp .env.example .env          # set PAYLOAD_SECRET
pnpm migrate                  # apply migrations
pnpm dev                      # http://localhost:3000, admin at /admin

pnpm typecheck                # tsc --noEmit
pnpm lint                     # eslint
pnpm build                    # production build (must pass before a PR)
pnpm generate:types           # regenerate src/payload-types.ts after changing a collection
pnpm generate:importmap       # regenerate the admin import map after adding admin components
pnpm migrate:create <name>    # generate a migration after changing a collection
pnpm jobs:run                 # background job worker
```

## Structure

```
├─ app/(payload)/       admin + API — generated by Payload, do not edit by hand

├─ fields/              shared fields: slugField, taxonomyStatusField, sortOrderField

└─ payload.config.ts    collections, storage, plugins
```

## Data model

| Collection slug | Table | Notes |
| --- | --- | --- |
| `photos` | photos | Upload collection; sizes thumbnail 320 / card 800 / large 1600 / xlarge 2560 (WebP) |
| `categories` | categories | Nested (nested-docs plugin adds `parent`, `breadcrumbs`); `path` = slug chain, e.g. `wildlife/big-cats/tigers` |
| `photo-collections` | photo_collections | The client's "Collections". Named so because "collection" is Payload's word for a table |
| `locations`, `tags` | locations, tags | Lookups |
| `cameras`, `lenses` | cameras, lenses | Built by the `gearCollection` factory in `collections/Gear.ts` |
| `media` | media | RAW versions and ambient audio |
| `bulk-upload-batches`, `bulk-upload-rows` | bulk_upload_* | Bulk Upload page storage |
| `users` | users | Single admin |

Many-to-many fields (a photo's categories, collections, tags) are `hasMany` relationships stored in `photos_rels`.

## Rules — keep these true when changing code

1. **Schema changes go through migrations.** `push` is off. After changing a collection: `pnpm migrate:create <name>` →
   review the generated SQL → `pnpm generate:types` → commit the migration, its `.json` snapshot, `migrations/index.ts`
   and `payload-types.ts` together. Never edit an already-merged migration; add a new one.
2. **Categories and photo-collections are never deleted.** `delete` access is `nobody`; use `status` (`active` /
   `hidden` / `archived`). Relationship pickers exclude archived entries via `filterOptions`.
3. **Public visibility:** photos are public only when `status = published`; categories/collections only when
   `status = active` (`publicWhenStatus`). Frontend code using the Local API runs with `overrideAccess: true` by
   default — pass `overrideAccess: false` or filter by status explicitly in public queries.
4. **No free-text taxonomy.** Categories, collections, locations, cameras, lenses and tags are their own tables;
   never store them as free text on a photo. This is what prevents spelling duplicates.
5. **EXIF auto-fill only fills empty fields** (`fillFromFile` in `collections/Photos.ts`). Never overwrite values
   the admin typed.
6. **Camera/lens matching** goes through `findOrCreateGear` (`lib/exif.ts`), comparing `matchKey()` values against
   `matchKeys`. Unknown gear is created with `needsReview: true`; don't create gear rows any other way.
7. **Slugs** come from `slugField()`; it de-duplicates with numeric suffixes. Don't hand-roll slug logic.
8. **`takenYear`** is derived from `takenAt` by a hook; never set it directly.
9. **Photos stay visible when one of their categories is hidden;** only the category drops out of the filter list.
10. **Don't edit generated files:** `src/payload-types.ts`, `src/app/(payload)/**`, `importMap.js`.

## Conventions

- TypeScript strict; import from `@/…` (maps to `src/`).
- Field names camelCase in code; Postgres columns become snake_case automatically.
- Admin descriptions are written for the client (plain English, no jargon).
- Use Payload's Local API (`getPayload({ config })`) on the server; don't call the REST API from server code.
- When calling `payload.create/update` on a union of collection slugs, branch per slug — Payload's types need a
  single literal slug.
- Prettier config in `.prettierrc.json` (single quotes, no semicolons, 120 columns).

## Checking changes

Before opening a PR: `pnpm typecheck`, `pnpm lint`, `pnpm build`, and `pnpm migrate` against a fresh database
when the schema changed. For behaviour changes in hooks, exercise them through the Local API with a small
`tsx --env-file=.env` script (create the docs, assert the result), then delete the script.
